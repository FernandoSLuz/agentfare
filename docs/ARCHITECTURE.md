# Architecture

AgentFare reads the session logs that Claude Code, Codex CLI and Gemini CLI already write, reduces each session to metadata and token counts, prices the tokens with a YAML table, and recommends where a cheaper model would have done the job. This page is the contract for contributors: which module owns what, and the invariants the tests enforce. The user-facing description is the [README](../README.md).

```text
logs (JSONL) --parsers--> SessionRecord --ingest--> SQLite --aggregate + PriceTable--> summary, sessions, models, report
                                                       |
                                                       +--> router --> advise (past sessions)
                                                       +--> router + runwrap --> run (before a task starts)
```

## Modules

Everything lives in `src/agentfare`.

| Module | Owns |
|---|---|
| `models.py` | `Usage` (five token buckets), `SessionRecord` (with its `slots`), `slot_of` (the UTC 15-minute slot of a moment), `AGENTS`, `cap_name` and `bounded` (a project, session id or model id is stored at most 200 characters long), `short_id` (the last 8 characters of a session id, because the first 8 of a Codex UUIDv7 are a timestamp that repeats for weeks) |
| `money.py` | Integer micro-cents (`1 cent = 1_000_000 ucents`), `EXACT_CONTEXT` for exact decimal math, `to_cents`, `usd_to_ucents`, `format_usd`, `format_usd_compact` (whole cents from $1 up), `ratio_str` |

| `cost.py` | `usage_cost_ucents`, `price_usage`, `reprice`: exact integer cost of a `Usage` |
| `db.py` | `Store` (three tables, schema version 3), `StoreError`, the in-place upgrade from versions 1 and 2, `Store.sessions` (filters and clips by slot time), `Store.whole_usage` (a session's tokens per model over its whole life), `Store.open_read_only`, `Store.session_copy` (the stored copy of a session, which ingest compares a second copy with), `Store.usage_range` (first and last slot with usage, for the empty-result hint) and `Store.reread_pending` (an upgraded database whose log files no ingest has read yet). A file with a newer `user_version` is refused and never touched, and the version is stamped only when it is lower |
| `ingest.py` | Incremental ingestion driven by each parser's `signature()` plus the idle gap and `parsers.PARSERS_VERSION`, `IngestReport` (with `files_failed` and `duplicates`) and `duplicates_warning`. A session found in more than one file is stored from the copy with the most tokens (`_keeps`) |
| `aggregate.py` | `priced_rows` (one `Row` per session, model and slot), `group_rows`, `period_for`, `load_rows`, and the warning helpers `model_warnings` and `unpriced_models` |
| `parsers/` | `base.LogParser` (the contract), `base.is_regular_file` (a named pipe is never opened), `PARSERS_VERSION` and one module per agent that exposes `PARSER` |
| `router.py` | Session scoring and recommendations for `advise` (`score_session`, `advise_sessions`, `weekly_savings`, `savings_split`), the pre-flight pick for `run` (`pick_for_run`, `count_files`). The switch or keep decision is taken on the whole session (its tokens per model from `Store.whole_usage`, like its tier) and only the money is split by slot and cut to the period, so the weekly rows add up. `Advice` carries `model` (the one that wrote the most inside the period) and `other_models` for the signature line. The `run` baseline is the model with the most spend for the agent in the last `BASELINE_DAYS` (30) days, counted back from the newest slot with spend in the database and never from the clock, else the most used overall, else the agent's heavy-tier model; `RunPick` records it as `baseline_basis` (`recent`, `all_time` or `configured`), `baseline_since` and `same_as_baseline` (aliases resolved), and `MIN_HISTORY` (5) past sessions of the same agent and tier are needed before their median replaces the default token budget |

| `render.py` | What the reporting commands share: the common options, `Filters` and `resolve_filters`, table drawing that degrades on a narrow terminal (`print_table`, see [Tables](#tables-on-a-narrow-terminal)), `empty_hints` (what every command says when its view is empty: on a database with no sessions at all two lines, one for `ingest` and `config` and one that points a new user at `init`, `doctor` and `demo`), `print_period_note`, `--json` helpers, the warning block (`price_warnings`, `print_warnings`), `clean_text` and `plain` for names from the logs, `SETUP_ERRORS` and `clean_errors` |
| `report.py` and `templates/` | The weekly report as data (`build_week_report`, with project names replaced by `Project A`, `Project B` unless asked; the default week is the one of the latest slot with spend; the saving is split into sessions a person prompted and background threads, and a week in progress has no percentage change) and its two Jinja templates, markdown and one self-contained HTML file with no script. The headline sentence is written in `commands/report.py`: it leads with the saving in the sessions a person prompted, gives the all-sessions figure second, and each percentage states its base when only some sessions could be compared |
| `pricefetch.py` | `prices --refresh`: downloads the source pages and compares them with the table. The only module that may touch the network; it refuses a host that is loopback, private, link-local or unspecified (or resolves to one), redirects included, unless `--allow-private-hosts` |
| `state.py` | `AppState`: lazy config, price table and store for one invocation, the config warnings (printed once, on stderr), the automatic ingest before a command reads data, and the stderr notes of a scan (`IngestProgress`: one line before the first file of an empty database, and `still reading <agent> logs...` once for an agent whose own scan has taken more than 2 seconds). `AppState.cfg` runs `Config.check()` and the local time zone warning, so a bad setting stops the commands that never ingest exactly like the ones that do. With `--no-ingest` on an upgraded database whose logs have not been re-read, `store()` prints one dim note (`APPROXIMATE_NOTE`: `database upgraded: day and week splits are approximate until agentfare ingest has re-read your logs`) |
| `setup_checks.py` | What `init` and `doctor` find out about a machine, so that the two always agree: `scan_agents` and `scan_root` count the files an ingest would read (through `parser.discover`) and add their sizes from the file system, capped at 100,000 files and 5 seconds per folder (the answer then says `at least N`), `source_origin` (whether a folder comes from the defaults, from `sources:` or from `CLAUDE_CONFIG_DIR`, `CODEX_HOME` or `GEMINI_CLI_HOME`), `find_cli` (an agent command is only looked up on `PATH` with `shutil.which`, never run), and the text helpers `tilde` (the home directory written as `~`, which keeps pasted output private), `human_size`, `count_text` and `wrap_text`. It never opens a log file |
| `cli.py` | The Typer app, the global options (`--config`, `--home`, `--no-ingest`, `--version`), which must come before the command (`_Group.invoke` answers `agentfare summary --no-ingest` with `agentfare --no-ingest summary`), `-h` as an alias of `--help`, Typer's `--install-completion` and `--show-completion` (the first edits the shell's startup files and runs only when asked, and no other command touches one), command registration, and `_entry`, which turns setup errors into one `error:` line with exit code 2 and a closed output pipe into a quiet exit |
| `commands/<name>.py` | One CLI command each, exposing `register(app)`: `init`, `ingest`, `config`, `summary`, `sessions`, `models`, `advise`, `run`, `report`, `prices`, `doctor`, `demo`. `run` never ingests and never creates the database: it opens an existing one with `Store.open_read_only`. `summary --top N` folds the projects and days beyond N into one `N more (total $X)` row only when that hides at least two rows (`summary._top`), and the table title says so | `init` is the 60-second setup: it scans with `setup_checks`, creates the data directory (0700), writes the config only with `--write-config`, ingests, and prints the total and the biggest saving (`--dry-run` stops after the scan). `doctor` is a read-only checklist of 18 checks with the stable ids `python`, `package`, `command`, `config`, `logs.<agent>`, `logs`, `cli.<agent>`, `data_dir`, `database`, `price_table`, `price_models`, `environment`, `terminal` and `network`, and every line that is not ok carries a `fix:`. It opens the database with `Store.open_read_only`, creates nothing, opens no log file, runs no agent, and a check that raises becomes a failed line. `demo` copies `src/agentfare/demo_data` (45 invented sessions, written by `scripts/make_demo_data.py`) to a temporary directory and runs the real `summary` and `advise` on it in process, with a temporary database and the clock frozen at `DEMO_NOW`. It ignores `--config` and `--home` and never reads the user's logs or `~/.agentfare`.

Every reporting command builds a plain dict of integers and strings first, which is exactly what its `--json` prints, and draws its tables from that dict, so the text and the JSON cannot disagree.

## The five token buckets

`Usage` holds five integers. Every parser maps its agent's counters onto them, so pricing is a plain product with nothing counted twice:

| Bucket | Meaning | Priced at |
|---|---|---|
| `input` | Uncached input tokens | `input` |
| `cache_read` | Input served from the prompt cache | `cached_input` (the input price when the table has none) |
| `cache_write` | Cache writes with the default 5-minute lifetime | `cache_write` (the input price when the table has none) |
| `cache_write_1h` | Cache writes with the 1-hour lifetime | `cache_write_1h`, then `cache_write`, then `input` |
| `output` | Output tokens including reasoning and thinking tokens | `output` |

`cache_write + cache_write_1h` is every token written to the cache. `cache_write_1h` is the last field so the first four stay positional.

| Agent | `input` | `cache_read` | `cache_write` | `cache_write_1h` | `output` |
|---|---|---|---|---|---|
| Claude Code | `input_tokens` | `cache_read_input_tokens` | 5-minute part of `cache_creation_input_tokens` | 1-hour part, capped at the total | `output_tokens` |
| Codex CLI | `input_tokens` minus cached minus written | `cached_input_tokens` | `cache_write_input_tokens` | 0 | `output_tokens` (already includes reasoning) |
| Gemini CLI | `input` minus `cached`, plus `tool` | `cached` | 0 (no write fee) | 0 | `output` plus `thoughts` |

Claude reports the cache buckets separately from `input_tokens`. Codex and Gemini report `input` including the cached part, so their parsers subtract it. [LOG-FORMATS.md](LOG-FORMATS.md) has the rest of each mapping.

## Money

Amounts are integer micro-cents. A price is a `Decimal` of dollars per million tokens, `cost.usage_cost_ucents` multiplies tokens by price in an exact decimal context, and it rounds half up once, at the end. Sums, shares and savings are integer arithmetic. Display goes through `money.format_usd` (two decimals for a whole cent, four otherwise) and `money.format_usd_compact` (whole cents from $1 up, which is what the tables print), and `--json` prints `{"cents": ..., "ucents": ...}` with shares in basis points.

## Money is attributed to when it was spent

The unit of cost is not the session but the **slot**: a UTC 15-minute window (`models.slot_of(ts)` gives `YYYY-MM-DDTHH:MM:00Z`). Every quarter hour is a whole number of minutes of every real UTC offset, so a slot is always inside exactly one local day and one local ISO week.

- **Parsers.** Each parser puts the tokens of every response under the slot of that response's own timestamp, in `SessionRecord.slots` (`{(slot, model): Usage}`). Per model the slots add up to `SessionRecord.usage`, because each parser builds both from the same responses in one pass. A response with no usable timestamp counts at the slot of the session's first timestamp. A record with no slots at all (a hand-built one) means "all of `usage` at the slot of `started_at`" (`SessionRecord.effective_slots()`).
- **Storage.** `session_usage` has one row per session, model and slot. `upsert_session` writes `effective_slots()`, normalising every slot through `slot_of`.
- **Reading.** `Store.sessions(agent, project, since, until)` filters by slot time in `[since, until)`: a session is returned when it has usage inside the range, its `usage` and `slots` are **clipped** to the range, and `StoredSession.clipped` says something was left out. Every other field (`tool_calls`, `files_touched`, `prompts`, `started_at`, ...) stays whole-session, so the complexity score of a session does not depend on the period you look at. With no range the whole session comes back. `Store.whole_usage(keys)` gives the whole-session usage per model of clipped sessions: `advise` and `report` score the session on it (the `input_tokens` signal) and decide on it whether to switch, and only then split the actual and the recommended cost by slot and cut them to the period.
- **Aggregation.** `aggregate.priced_rows` yields one `Row` per (session, model, slot), each priced and rounded on its own, with the local day and week of the slot in the configured timezone. `Group.sessions` is a set of session keys, so a session that spans two days is one session in each day's row and once in the total. Never count rows as sessions.

The consequence every command relies on: the numbers for a period are the money spent inside that period, so `summary`, `sessions`, `models`, `advise` and `report` show the same total for the same period, and a session that spans the edge of a period shows only what it spent inside it.

## The database

`db.Store` wraps one SQLite file (default `~/.agentfare/agentfare.db`, stdlib `sqlite3`):

| Table | Holds |
|---|---|
| `sessions` | One row per session: `key` (`<agent>:<session_id>`), `agent`, `session_id`, `project`, `started_at`, `ended_at`, `wall_seconds`, `active_seconds`, `tool_calls`, `files_touched`, `error_retries`, `turns`, `prompts`, `primary_model`, `source_path`, `ingested_at` |
| `session_usage` | One row per session, model and slot (primary key `key, model, slot`): `input`, `cache_read`, `cache_write`, `cache_write_1h`, `output`, with an index on `slot` |
| `ingested_files` | `path`, `agent`, `signature`, `sessions`: what was parsed, so an unchanged file is skipped |

`PRAGMA user_version` holds the schema version, currently 3. Version 2 added `session_usage.cache_write_1h`, version 3 added `session_usage.slot` and made it part of the primary key. A version 1 or 2 file is upgraded in place on open: the `session_usage` table is rebuilt, its old rows go to the slot the session started in, and `ingested_files` is emptied, so the next ingest re-reads the logs, splits the cache writes by lifetime and puts every response in its own slot. Concurrent commands are safe because the upgrade runs under `BEGIN IMMEDIATE` and re-checks after taking the lock. A file whose version is higher than the code's is an error (`the database ... was written by a newer agentfare; upgrade agentfare or delete the file`): it is not upgraded, written or stamped. The version is stamped only when it is lower, so opening a current file takes no write lock. After an upgrade `ingested_files` is empty, and `Store.reread_pending()` is true while a stored session's log file exists that no ingest has read since: with `--no-ingest` it is what makes `AppState` print the approximate-splits note. `Store.open_read_only` opens the file as it is, without creating, upgrading or stamping anything, and refuses one of another schema version (`run` uses it and falls back to its default token budgets, and `AppState` uses it for `--no-ingest` on an existing database of the current version, so a read-only file still answers; any other case takes the normal `Store(path)`).

**The stored file signature** is `<parser signature>|gap=<idle gap in seconds>|p=<parsers.PARSERS_VERSION>`. The parser signature says whether the file changed; the other two make a setting or a release that changes what the parsers produce invalidate the parsed files, so the logs are re-read without `--full`. Bump `PARSERS_VERSION` whenever any parser's output for the same log changes. `IngestReport.sessions` counts the distinct sessions stored by a run and `sessions_read` the records stored (a session resumed in another file counts again), which is what `ingest` prints: `read N session records from M files (P parsed, Q unchanged); the database holds K distinct sessions`.

**One session in several files.** The same session can sit in two log files that no parser merges (an archived log and its live copy, two configured roots). `ingest._keeps` compares the incoming record with `Store.session_copy`: the copy with the most tokens wins, on a tie the later source path, so the result does not depend on the order the files were parsed in, and a newer read of the very file a stored session came from always replaces it. Sessions that had more than one copy are counted in `IngestReport.duplicates` and named in one warning, by `ingest` and by the automatic ingest. `ingest --json` carries `duplicate_sessions` and `files_failed` (files that could not be read or parsed, each also in `errors`) next to the other counts.

`StoreError` is what every failure to open, create, upgrade, read or write the database becomes (a file that is not a database, a permission problem, a malformed file). Its message names the file and, for a damaged one, says that deleting it rebuilds it from the logs that still exist; for a folder that cannot be made or written (a read-only home) it says to set `AGENTFARE_HOME` or `--home`. It belongs to `render.SETUP_ERRORS` together with `ConfigError` and `PricingError`: a command prints `error: ...` and exits with code 2, and `ingest.ingest` re-raises it instead of recording it as one bad file, because every other file would fail the same way.

## Tables on a narrow terminal

`render.print_table` sets the column widths itself, so that only a column with a `min_width` ever loses characters and a number is never cut. Every column is at its natural width with two spaces between columns when that fits. Otherwise the gap is one space and the shortenable columns are cut, the widest first, down to their floors (`Col.cut_last` columns after the others). A floor is `min_width`, or wider where two different cells would be cut to the same text (`_unique_width`), so two models never show as one label. Model columns use `MODEL_MIN` (18, one more than `claude-sonnet-5-5`) and are cut at their tail, never inside a number (`claude-opus-4-5-...`, not `claude-opus-4-5-2025...`); `Col.middle` would cut in the middle, and no command sets it.

If the table still does not fit, the columns with `Col.optional` are left out one at a time, the lowest number first, and the cuts are tried again after each. A dim line under the table names what was left out (`left out to fit 60 columns: Provider, List out $/1M; --json has everything`). As a last resort the shortenable columns go past their floors down to their headers, and if that is not enough the table is drawn wider than the console, because a cut figure is worse than a wrapped line. `Whole` marks a label that is not cut while its column can be as wide as it, such as the `2 more (total $0.98)` row of `summary --top`. On a console whose encoding cannot write `…`, `█` or `→`, the table uses `~`, `#` and `->`.

## Invariants

The tests enforce these. Break one on purpose only with a test that says why.

1. Privacy. No prompt or reply text, tool input or output, or file contents are stored. `files_touched` is a distinct count and `project` is a basename. Every parser test plants a `PRIVACY-CANARY-*` marker in each content field of its fixture and asserts that the marker is not in the `SessionRecord`, and `tests/test_e2e_fixtures.py` asserts that it is not in the bytes of the data directory after an ingest of all three fixtures (the Codex and Gemini parser tests check the database file as well). `source_path` and `ingested_files.path` hold log file paths (for Claude Code that includes the encoded working directory), and `report` hides project names unless `--show-projects` is given.
2. Money is integers. Cost math uses `Decimal` prices and integer token counts, rounds once, and never touches a `float`.
3. Unverified prices are loud. A model whose input or output price is `unverified`, or that is missing from the table, is excluded from dollar totals, and every command that shows money prints a warning naming it (`render.price_warnings`, built on `aggregate.model_warnings`). A priced model with an unverified optional price (cached input, cache write) is counted at a fallback rate and named too. `advise` gives no advice on a session with unpriced usage.
4. No network except `agentfare prices --refresh`. Only `pricefetch.py` may import a network-capable module, only `commands/prices.py` may import `pricefetch`, and only lazily, inside the refresh path. `tests/test_no_network.py` checks this with a static scan of the source (including lazy and dynamic imports) and a runtime guard that blocks sockets and process creation while every other command runs against the fixtures.
5. Token normalisation. Every parser fills the five buckets as described above and attributes tokens to the model that served each response and to the slot in which it was made.
6. Determinism. `AGENTFARE_NOW` freezes "now", `AGENTFARE_HOME` moves the data directory, and the config `timezone` decides day and week bucketing (the fixtures use UTC).
7. Period totals agree. Money belongs to the slot it was spent in, so for one period every command shows the same total, and a clipped session shows only what it spent inside the period while its counters and score stay whole-session (`tests/test_core_aggregate.py` and `tests/test_e2e_slots.py` check this across midnight and week boundaries in several timezones).
8. One source for the defaults. `config.DEFAULT_CONFIG_YAML` is what `agentfare config --init` writes and what is parsed for the defaults, so the documented file and the real defaults cannot differ.
9. Setup problems are one line. A bad config, price table or database is an `error: ...` line and exit code 2, never a traceback (`cli._entry`, `render.clean_errors`).
10. Names from the logs are data. Project and model names, file names and the text of an error reach the terminal and the report through `textsafe.clean_text` (also exported as `render.clean_text`) or `render.plain`, which replace control characters, line separators and bidirectional overrides with `?`.
11. What AgentFare writes is private and what it reads may be hostile. New directories are 0700 and new files 0600, and nothing is written through a link somebody planted (`safeio`). A YAML file that expands to a huge structure is refused before anything converts it (`safeyaml`). Only regular files are read as logs, so a named pipe cannot hang a scan (`parsers.base.is_regular_file`). `tests/test_hardening_files.py`, `test_hardening_parsers.py`, `test_hardening_yaml.py` and `test_hardening_text.py` check each of these, and the ones that could hang or exhaust memory run in a child process with a timeout or an address-space limit.
12. The docs cannot drift. `tests/test_readme.py` runs the README's output blocks, rebuilds its generated tables from `pricing.yaml` and `DEFAULT_CONFIG`, recomputes the figures of its worked example and narrative, parses every documented command and checks the relative links.
13. The setup commands are safe to run anywhere. `doctor` only looks: it opens no log file, writes nothing (not even the data directory), runs no agent and uses no network, and a failing check becomes a line instead of a traceback. `init` never changes the agent folders, never overwrites an existing config and is idempotent. `demo` never reads the user's logs or `~/.agentfare`. The `tests/test_init_cmd.py`, `tests/test_doctor_cmd.py` and `tests/test_demo_cmd.py` files check each of these, and `tests/test_no_network.py` runs all three under its guard.

## Adding to it

- A parser: [LOG-FORMATS.md](LOG-FORMATS.md#adding-an-agent) has the contract and the steps.
- A model price: edit `src/agentfare/data/pricing.yaml` from the provider's page, see [CONTRIBUTING.md](../CONTRIBUTING.md#add-a-model-price).
- A command: one module in `commands/` that exposes `register(app)`, added to the import and the registration loop in `cli.py`, with its output built as a dict first.

## Testing conventions

- `tests/fixtures/` holds synthetic logs in each agent's real on-disk format, and `tests/fixtures/config.yaml` (relative paths, `timezone: UTC`) to run them. Their text is obviously fake and carries the canary markers.
- [`tests/fixtures/EXPECTED.md`](../tests/fixtures/EXPECTED.md) works out by hand, token by token and price by price, the dollars, router signals, savings and `run` estimates of the three sample sessions. `scripts/verify_fixtures.py` re-derives them from the raw logs and `pricing.yaml` without importing `agentfare`, and `tests/test_e2e_fixtures.py` asserts those numbers, as literals, against the real CLI. A price change fails it on purpose, so that the expected dollars are re-verified instead of following the table. `scripts/verify_fresh_clone.sh` proves that a fresh clone installs, runs the demo and passes the suite.
- `tests/conftest.py` points `HOME` and `AGENTFARE_HOME` at throwaway directories and clears `AGENTFARE_CONFIG` and `AGENTFARE_NOW` before every test. No test may touch the network or the real `~/.agentfare`, `~/.claude`, `~/.codex` or `~/.gemini`.
- CLI tests drive the app with `typer.testing.CliRunner` or a subprocess against the fixture config, with a temporary `AGENTFARE_HOME`, `AGENTFARE_NOW=2026-09-30T12:00:00Z` and a pinned `COLUMNS` wherever output width matters.
